- **Nota de escopo (decisão de design, sem ADR formal disponível para esta tarefa até agora):**
  - O diagrama de arquitetura (README §2, nó "EDGE: Entrada HTTP e roteamento da migração") descreve um componente de borda que decide, por tenant/capacidade, se uma requisição vai para o BFF, para a API Go ou para o Node legado. Um proxy HTTP real de borda (nginx/gateway) que efetivamente encaminhe tráfego para o processo Node legado é **infraestrutura de implantação**, não código de aplicação Go, e está fora do alcance desta tarefa/checkout (não há processo Node legado acessível neste ambiente de execução para testar contra ele).

Registrado como decisão em ADR-0008.

  - "Bloquear caminhos alternativos, inclusive jobs": o mesmo par registro+guarda é usado tanto pela rota HTTP de exemplo (`cmd/server`) quanto pelo job placeholder (`cmd/worker`) — não é uma checagem duplicada por processo.

**Achado de design durante a implementação:** o desenho inicial (`Acquire` consultando `OwnerOf` no banco a cada chamada, sem cache) tinha uma corrida real — uma leitura concorrente com `SwitchOwner` podia observar o owner antigo depois que o novo já fora persistido, admitindo trabalho sob uma decisão já revogada, violando "escritor único". Corrigido movendo o owner para um cache em memória na própria `Guard`, mutado só dentro da mesma seção crítica que libera admissão (`resumeWithOwner`, chamado por `SwitchOwner` só depois da escrita no banco confirmada). Ver ADR-0008 para a decisão completa.

**Achado de teste durante a implementação:** uma primeira versão do teste de "escritor único" comparava timestamps de relógio de parede entre goroutines concorrentes e produziu falsos positivos (10 "violações" registradas) — o atraso de agendamento do runtime Go entre `Acquire` retornar e a goroutine chamadora ler `time.Now()` pode ultrapassar a janela real da seção crítica. Substituído por um teste determinístico com espera ativa sobre o estado observável (`TestSwitchOwner_NoAdmissionOnceDrainingConfirmed`), no mesmo padrão de `shutdown_test.go`. Um segundo bug de teste (não de produção) também apareceu nesse processo: o próprio polling ativo, ao chamar `Acquire` sem liberar admissões concedidas antes da drenagem começar, prendia `SwitchOwner` esperando um trabalho que nunca terminaria — corrigido liberando cada admissão de polling imediatamente.
