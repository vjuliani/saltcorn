### Subtarefas e decisões

1. Protocolo 1: scope tenant/ator/tabela, IDs idempotentes por dispositivo, versão-base, resultados por operação, schema versionado e snapshot completo autorizado. Limites (100 operações, 1 MiB, 2000 linhas) são explícitos e rejeitam sem commit parcial. Diferenças de cursor/LWW/PKs/FKs em ADR-0011.
2. Backend: fila/resultado/evento na mesma transação de registro; savepoint para conflito/constraint; papel atual resolvido no banco, GUCs para RLS, corte pela capacidade `tables.records`. Provisionamento da outbox separado da requisição.
3. Cliente: uma escrita CAS confirma snapshot/fila/conflitos/checkpoint; IDs persistidos antes da rede; nova tentativa usa o mesmo payload. Formato local 1→2 aditivo, versões futuras recusadas sem escrita, conflitos de schema preservados. Revogação bloqueia cache sem apagar pendências, inclusive se ocorrer no pull de refresh de schema.
4. Runtime: `mobileApp.syncV1.open` usa sessão/CSRF do BFF e driver SQLite existente. API de leitura/edição/conflito documentada; nenhum switch automático dos modelos offline legados. Pacotes JS/nativos existentes mapeados no ADR.
5. CI dedicada `migracao-sync-ci`: Node 22, SQLite real, BFF e Go/PostgreSQL, com teste E2E obrigatório (`SALTCORN_GO_TEST_MOBILE_E2E=1`).

### Falhas observadas e corrigidas

- E2E após upgrade de schema falhou com `cached plan must not change result type` no PostgreSQL: os comandos de registros usavam `RETURNING *` em statements já preparados. Corrigido para listar explicitamente as colunas do catálogo, mudando a chave SQL do cache quando o schema muda. E2E passou depois; suíte inteira de records/backend revalidada.
- Teste RLS com usuário não proprietário falhou ao executar DDL da outbox (`must be owner of table _sc_outbox`). A preparação passou para `sync.EnsureSchema`, durante provisionamento; `Exchange` não executa DDL. Teste sem superuser/bypass agora passa, incluindo USING, WITH CHECK, revogação e replay sem vazar linhas.
- Tentativa de testes HTTP no sandbox falhou por sockets bloqueados; repetida com acesso aprovado e aprovada. Não é falha ignorada do produto.
- `npm run build --prefix packages/saltcorn-mobile-app` falhou por dependências Capacitor que o builder instala dinamicamente e que faltavam no checkout. Instalei em `/tmp/go031-mobile-deps`, sem mudar manifest/lockfile do projeto, as versões do builder. O bundle completo passou usando esse diretório de resolução. Uma primeira chamada programática usou cwd incorreto e não achou preset Babel; corrigido para o diretório do app.
- Geração/build dos contratos Go exigiu escrita no cache Go fora do sandbox; repetido com permissão aprovada. Nenhuma ação foi rejeitada pela revisão automática.
